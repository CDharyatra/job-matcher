HOW TO GET FRONTIER QUALITY AT $0
==================================================

Money is banned. Stupidity is also banned. Use this quality strategy:

1. Deterministic first, LLM second.

Most job-routing is not a creative writing task. Parse years, locations, CTC/LPA, remote flags, Easy Apply vs external, duplicates, and blocklists with plain code. That is free, faster, more reliable than an LLM, and it is how you keep quality high when rate limits hit. An LLM that invents "8 years of Kubernetes" when the resume has none is worse than a regex.

2. Local first-pass retrieval, also free.

Use local BM25 / keyword overlap / skill taxonomy / title synonym lists to discard obvious misses before any model is called. Example: a Python backend resume should not spend an NVIDIA call on a WordPress intern role. This is how DeepSeek-class models stay within free RPM/RPD caps without lowering match quality.

3. Spend the scarce free LLM budget on the hard cases only.

Call the strongest $0 model for: resume structured extraction once (cache the profile JSON), borderline match decisions, evidence-backed rationales, cover-note drafts from existing bullets, and mapping a screening question onto a facts-file field. Do not call it for every job in a 400-result dump.

4. Route models by job, not by ego.

Default proposed routing, to be confirmed against live catalogs and LiveBench:

- Judge / matcher / rationale writer: best available of DeepSeek V4.1 Flash, DeepSeek V4 Pro 0813, Kimi K3, GLM-5.3, via NVIDIA. Prefer the one with the highest LiveBench Agentic Coding plus Instruction Following among those actually returning 200s on the user's key.
- Bulk classify (easy_apply vs external, spam vs real, obvious no-match): faster $0 model such as GLM-5.3 Flash, Qwen 3.8 Flash, or Nemotron Lightning Free.
- Long messy job descriptions: Kimi K3 or DeepSeek V4.x because of long context.
- Code you write for this repo: you are the coding agent. For any in-project codegen helpers, prefer the best $0 Agentic Coding model from LiveBench. DeepSeek V4.1 Flash was the Agentic Coding leader in the snapshot above.

5. Cache everything.

Cache resume profile JSON, company quality notes, normalized job text hashes, and LLM rationales keyed by (resume_hash, job_hash, prompt_version). A second pipeline run on the same job must cost zero extra tokens.

6. Structured outputs with validation.

Every LLM call that affects routing must return JSON that your code validates. If JSON is invalid or required evidence fields are empty, retry once on the same model, then fallback to another $0 model, then fall back to inbox-instead-of-apply rather than auto-applying garbage. Quality here means: never silently accept garbage.

7. Redact PII before cloud inference.

NVIDIA trial terms for some free endpoints say trial use only and tell you not to submit personal or confidential data. Muse Spark 1.3 Contributor Free may use prompts to train future Meta models. Therefore: strip name, email, phone, address, links, and company names that identify the user from text sent to any hosted model when possible. Send skills, titles, dates as ranges, and de-identified bullets. Keep the full resume and candidate_facts.yaml on disk only.

8. Fallbacks when NVIDIA 429s.

NVIDIA free tiers are commonly about 40 requests per minute, and some popular models (Kimi K3 especially) have much tighter daily caps. Implement exponential backoff, a per-model daily budget, a queue, and automatic failover: matcher primary -> matcher secondary -> deterministic-only mode. If the LLM is down, still collect jobs, still score with deterministic features, still auto-apply only when deterministic match is clearly 70 through 90 with no missing facts. If the deterministic score is borderline, email instead of apply. Down does not mean "do nothing." Down means "degrade gracefully without paying."

The user got Muse Spark 1.3 for free through OpenCode Zen PLUS NVIDIA keys. That is the pattern: reuse free paths, not Zen's paid catalog. Paid Muse Spark 1.3 is about $1.25 input / $4.25 output per million tokens on Zen. That is not $0. Use muse-spark-1.3-contributor-free or NVIDIA instead.

==================================================
MATCHING QUALITY BAR
==================================================

A 70 means the person on the resume could credibly do the job as written. Not "they could learn it." Not "the title has Engineer in it."

Handle title synonyms, mandatory vs optional requirements, years as ranges, stack aliases (Postgres, JS, k8s), domain mismatch, laundry-list consultancy posts.

Always produce evidence: which resume bullets map to which requirements. No evidence, no match.

If half the feed scores above 90, the scorer is broken. The 90 band should be rare.

Tune on at least 50 labeled jobs. Do not enable live submit until auto-apply precision for the 70-90 set is at least 80 percent. Until then, dry-run: score, write what would have been applied, email those as dry-run, do not click submit.

If free-model output is worse than the deterministic scorer, trust the scorer and email instead of apply.

- Never submit a different person's resume.
